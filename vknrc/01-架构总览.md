# 01 · 架构总览

## 1. 项目定位

VkNRC 是一个**实时路径追踪 + 神经网络辐射缓存(NRC)**的 Vulkan 渲染器。它把一个"完整渲染器"拆成两个层次:

1. **MyVK 库层**(`dep/MyVK/`):通用的 Vulkan 封装,包括
   - `myvk` 命名空间:对 Vulkan 对象(Buffer、Image、Pipeline、CommandBuffer……)的 RAII 封装,基于 volk + VMA。
   - `myvk_rg` 命名空间:一套**渲染图(Render Graph)**框架,用声明式 API 描述每帧的 Pass 与资源依赖,自动完成调度、内存分配、屏障与描述符绑定。
2. **应用层**(`src/` + `shader/`):具体的渲染器实现,把场景加载、加速结构、NRC 状态与若干渲染 Pass 组合成一张渲染图。

> 设计意图:渲染图框架把"我该在什么时候插入 barrier、如何复用内存、如何安排 RenderPass 子通道"这些**机械性工作**从应用逻辑中剥离,让应用只关心"画什么、数据依赖什么"。这也是本项目与 tiny-cuda-nn 官方示例最大的工程差异。

## 2. 总体架构分层

### 2.1 各层职责

| 层 | 职责 | 关键约束 |
| --- | --- | --- |
| 应用层 | 渲染目标、渲染策略(左/右半屏分别用不同方法对比)、训练调度 | 不直接调用 Vulkan API,全部经由 myvk |
| 着色器层 | 所有 GPU 计算:光栅化、路径追踪、MLP 前向/反向、优化器 | GLSL 460+,依赖 `GL_NV_cooperative_matrix` 等扩展 |
| 渲染图框架 | 把声明式渲染图编译成可执行的 Vulkan 命令序列 | 事件驱动增量编译,按需重编译子阶段 |
| Vulkan 封装 | RAII 管理 Vulkan 对象生命周期、VMA 内存、命令录制 | 线程安全的 Ptr 引用计数 |
| 运行时 | Vulkan 驱动、窗口、数学库等 | — |

## 3. 帧渲染管线(一帧的完整流程)

每帧由 `main.cpp` 主循环驱动:`frame_manager->NewFrame()` 获取当前帧命令缓冲,然后执行渲染图 `NRCRenderGraph::CmdExecute`。

```
┌─ 帧开始 ─────────────────────────────────────────────────────────┐
│                                                                  │
│ ① VBufferPass (Graphics)                                         │
│    · 用简单深度渲染写出 uvec2 (primitive_id, instance_id) 到      │
│      v_buffer (R32G32_UINT),深度缓冲 D24_UNORM_S8_UINT            │
│    · 目的:路径追踪不再做整场景求交,而是直接从像素的 V-Buffer      │
│      定位可见三角形,省掉第一段 ray query                          │
│                                                                  │
│ ② PathTracerPass (Compute, 8×8)                                  │
│    · 每像素一条主光线,命中 V-Buffer 三角形后开始路径追踪          │
│    · 逐 bounce:ray query 求交 → CookTorrance BRDF 采样 → 累计     │
│    · 按概率(默认 3%)对像素分配"训练模式"或"推理模式"             │
│    · 写出:                                                        │
│      - 图像 bias_factor_r (rgba32f): 累加 radiance + factor.r    │
│      - 图像 factor_gb (rg32f): factor.g/b                        │
│      - eval_records 缓冲(按需,紧凑打包)                          │
│      - batch_train_records[4] 训练记录缓冲(仅训练模式)           │
│                                                                  │
│ ③ NNGenIndirect (Compute, 1×1)                                   │
│    · 把 eval_count 换算成 indirect dispatch 命令                  │
│    · (NNDispatch 模板的 "gen_pass")                              │
│                                                                  │
│ ④ NNInference (Compute, indirect dispatch, subgroup 16/32)       │
│    · 全融合 MLP 前向:对每条 eval record 推理出辐射缓存预测        │
│    · 屏幕像素:eval → 屏幕输出(写回 bias_factor_r)                │
│    · 训练批次:eval → 把预测合入 batch_train_records 的 bias 项    │
│                                                                  │
│ ⑤ 训练批次 b=0..3 (每个批次一组 Pass):                           │
│    · BufferFillPass: 清零 gradients 缓冲                          │
│    · NNPreparePass (1×1): 裁剪 count、生成 indirect cmd、更新     │
│      optimizer_state(step/beta/alpha 衰减)                       │
│    · NNGradient (indirect dispatch): 反向传播求梯度,原子累加      │
│      dW 到 gradients                                              │
│    · NNOptimizer (WeightCount/64): Adam 更新权重,可选 EMA         │
│      (最后一个批次额外更新 use_weights)                          │
│                                                                  │
│ ⑥ ScreenPass (Graphics)                                          │
│    · 子通道读取 NNInference 输出的颜色作为 input attachment       │
│    · 可选累积(accumulate 图像 + count 平均)                      │
│    · Hejl 2015 Filmic 色调映射 + gamma,写到 swapchain             │
│                                                                  │
│ ⑦ ImGuiPass (Graphics)                                           │
│    · 叠加调试面板,输出到 swapchain                                │
│                                                                  │
│ ── 提交:FrameManager::Render() 呈现 ──                           │
└──────────────────────────────────────────────────────────────────┘
```

### 3.1 数据流图(资源级)

```
v_buffer ──────────► PathTracer ──► bias_factor_r ─┐
depth                │             factor_gb        │
                     │                              ▼
                     │  eval_records ─────► [NNGenIndirect] ─► NNInference ─► color ─► ScreenPass ─► ImGuiPass ─► swapchain
                     │       ▲                │                     │
                     └───────┴────────────────┴── batch_train_records[4] (经 NRCInference 写入预测 bias)
                                                                    │
                      (每批次) batch_train_count ──► BufferFill ─► NNPrepare ─► NNGradient ─► NNOptimizer ─► weights / use_weights / optimizer_*
```

**关键点:**

- `eval_records` 是一个**紧凑、按需增长**的记录缓冲:只有命中"需要 NRC 求值"的像素才追加记录(通过 `atomicAdd` 计个数),而不是每个像素固定一条。这样 `NNInference` 的 dispatch 次数 = 实际求值数。
- `batch_train_records[b]` 中的 `bias` 字段先由 PathTracer 写入"后续 radiance",再由 NNInference 改写为"辐射缓存预测值",供 NNGradient 作为 L2 目标。
- `weights`(fp16)供 NNGradient 读;`use_weights` 是**渲染用权重**,由最后一个优化器批次按 EMA 或直接拷贝写入,NNInference 只读它。

## 4. 模块划分与依赖关系

```
main.cpp
  ├─ Camera
  ├─ Scene(CPU 数据)
  ├─ VkScene ──► VkSceneBLAS ──► VkSceneTLAS
  ├─ VkNRCState
  └─ rg::NRCRenderGraph ── 由 N 个 Pass 组成
       ├─ VBufferPass ──(Graphics)
       ├─ PathTracerPass ──(Compute)
       ├─ NNDispatch<NNInference> ──(PassGroup: gen_pass + pass)
       ├─ NNTrain × 4 ──(PassGroup: clear + prepare + gradient + optimizer)
       ├─ ScreenPass ──(Graphics)
       └─ myvk_rg::ImGuiPass
```

依赖方向自底向上:**myvk(封装)→ myvk_rg(框架)→ 应用层 Pass → NRCRenderGraph → main**。应用层不反向依赖框架内部实现。

## 5. 线程模型

- **单主线程**:窗口事件、ImGui、CPU 状态更新、命令录制都在主线程顺序完成。
- **VkScene 纹理加载多线程**:`VkScene::load_textures` 用 `std::async` 并发加载贴图,每个工作线程持有自己的 `CommandPool`,通过原子计数器分配纹理 ID——这是全项目唯一的多线程 GPU 提交点,且只在启动阶段执行。
- **GPU 并行**:3 重帧缓冲(frame count = 3)允许 CPU 提前录帧、GPU 流水并行;每帧渲染图内部则完全顺序化(单队列提交)。

## 6. 关键设计决策

1. **用 VK_NV_cooperative_matrix 而非 KHR**:KHR 版对矩阵尺寸/布局限制太多,无法实现论文中 16×16 fp16 块的全融合 MLP;NV 扩展在 NVIDIA 驱动上可用 `coopMatMulAddNV` 自由控制布局。
2. **V-Buffer 加速首段求交**:可见性用传统光栅化解决,避免每像素发第一条 ray query,显著降低路径追踪起点开销,并让"左/右半屏方法对比"成为可能(每像素只需一次即可定位三角形)。
3. **渲染图声明式调度**:所有资源同步/布局转换由 myvk_rg 统一生成 barrier;Pass 通过 `AddDescriptorInput` 声明 binding,框架生成描述符集。
4. **权重双缓冲(weights / use_weights)+ EMA**:训练权重与推理权重解耦,EMA 平滑推理权重,减少训练噪声对渲染的干扰;UI 可切换是否使用 EMA。
5. **累积计数由 CPU 管理**:`VkNRCState` 维护 `m_accumulate_count`,仅当需要累积(如对比降噪效果)时 ScreenPass 才做时域平均,`accumulate` 图像跨帧保留。

## 7. 与本项目 README 声称的对应关系

README 声称"反传性能优于 tiny-cuda-nn",其工程基础在于:
- 前向/反向全部融合进**单个 compute shader**(`nrc_gradient.comp`),权重矩阵以 fp16 协作矩阵块在共享内存与寄存器间流转,无中间激活落盘;
- 梯度通过 `GL_EXT_shader_atomic_float` 的 fp32 原子加跨 subgroup 归约;
- 一次 dispatch 覆盖 16K 训练样本(间接调度),批间仅通过渲染图串接,无 CPU 往返。
