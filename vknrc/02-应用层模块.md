# 02 · 应用层模块详解

本文档逐一分析 `src/` 下的应用层模块:入口、相机、场景加载、GPU 场景、加速结构、NRC 状态。每个模块包含:职责、关键数据结构、实现方案、设计权衡。

---

## 1. `main.cpp` — 程序入口与主循环

### 1.1 职责

- 解析命令行 OBJ 路径,加载场景;
- 创建 GLFW 窗口、Vulkan Instance/PhysicalDevice/Device;
- 构建场景加速结构与 NRC 状态;
- 运行主循环:处理输入 → 更新 ImGui → 提交渲染图 → 呈现。

### 1.2 设备选型(关键逻辑)

```cpp
for (const auto &candidate_physical_device : myvk::PhysicalDevice::Fetch(instance)) {
    if (candidate_physical_device->GetExtensionSupport(VK_NV_COOPERATIVE_MATRIX_EXTENSION_NAME)) {
        physical_device = candidate_physical_device;
        break;   // 必须支持 NV 协作矩阵
    }
}
```

选择第一个支持 `VK_NV_cooperative_matrix` 的物理设备。随后按 `features.vk12.pNext` 链式挂载扩展特性:

```
vk13.pNext → AccelerationStructure(KHR) → RayQuery(KHR) → CooperativeMatrix(NV) → ShaderAtomicFloat(EXT)
```

依次启用的特性:
- `vk11.storageBuffer16BitAccess` — fp16 权重存储访问;
- `vk12.bufferDeviceAddress` — 加速结构构建所需的设备地址;
- `vk12.hostQueryReset` — 主机侧重置 query pool;
- `vk12.shaderFloat16` — shader 内 fp16;
- `vk12.vulkanMemoryModel(+DeviceScope)` — 原子操作跨队列域可见性;
- `vk13.computeFullSubgroups` / `subgroupSizeControl` — 全子组协作矩阵执行;
- `shaderBufferFloat32AtomicAdd`(EXT)— 梯度 fp32 原子累加;
- `cooperativeMatrix`(NV);
- `rayQuery` / `accelerationStructure`(KHR)。

> 注释要点:这些特性是一环扣一环的——协作矩阵需要完整子组执行,原子浮点需要内存模型保证可见性,ray query 需要加速结构。缺任何一个都无法运行。

### 1.3 主循环结构

```cpp
while (!glfwWindowShouldClose(window)) {
    // 1. 计算帧间隔 delta
    // 2. glfwPollEvents(); ImGui 新帧;渲染控制面板
    // 3. 相机 DragControl(WSAD + 鼠标拖拽)
    // 4. 根据 UI 状态更新训练概率(lock 时置 0,否则 3%)
    // 5. frame_manager->NewFrame():
    //      命令缓冲 Begin → render_graph->CmdExecute → End → frame_manager->Render()
    // 6. vk_nrc_state->NextFrame():累积计数 +1,更新随机种子
}
```

**设计要点:**

- **每帧重建累积种子**:`NextFrame()` 用 `std::uniform_int_distribution` 刷新 `m_seed`,保证路径追踪每帧不同噪声,便于累积去噪;
- **渲染图跨帧复用**:创建了 `kFrameCount` 个 `NRCRenderGraph`,每帧取 `frame_manager->GetCurrentFrame()` 对应的那张图(与帧内 in-flight 资源对应);
- **窗口 resize 回调**重置累积图像与计数,避免分辨率变化导致累积错位。

## 2. `Camera` — 自由视角相机

### 2.1 数据结构

```cpp
glm::vec3 position;         // 相机位置
float yaw, pitch;           // 欧拉角
float fov = π/3;            // 视场角
```

### 2.2 视图矩阵构造(与 Vulkan 坐标系匹配)

```cpp
glm::mat4 GetVkViewProjection(float aspect, float near, float far) const {
    glm::mat4 ret = glm::perspectiveZO(fov, aspect, near, far);
    ret[1][1] *= -1;                          // 翻转 Y:Vulkan NDC 的 Y 向下
    ret = glm::rotate(ret, -pitch, {1,0,0});  // 先绕 X 轴(pitch)
    ret = glm::rotate(ret, -yaw,   {0,1,0});  // 再绕 Y 轴(yaw)
    ret = glm::translate(ret, -position);
    return ret;
}
```

注意:使用 `perspectiveZO`(Vulkan 风格 0..1 深度),并手动 `ret[1][1] *= -1` 翻转 Y,因为 Vulkan 裁剪坐标 Y 轴向下,而 GLM 默认向上。

### 2.3 光线基向量

`GetVkLookSideUp(aspect)` 返回:

- `look`:相机朝向(单位向量);
- `side = normalize(side) * tan(fov/2) * aspect` —— 已按宽高比缩放,这样屏幕坐标 `[-1,1]` 直接乘以 side/up 即为像素方向:
  `ray.d = normalize(look + clip.x * side + clip.y * up)`;
- `up = normalize(cross(look, side)) * tan(fov/2)`。

### 2.4 输入控制

- `DragControl`:WSAD 平移(平面内)、Space/Shift 升降、按住鼠标左键拖拽旋转视角,俯仰角 clamp 到 ±90°,yaw 循环取模;
- 若 ImGui 窗口获得焦点则不响应相机输入(避免与 UI 冲突);
- 返回 `*this != prev_cam` 表示相机是否变化,供 main 判断是否重置累积计数。

## 3. `Scene` — CPU 场景数据

### 3.1 数据结构

```cpp
std::vector<glm::vec3>      m_vertices;        // 顶点位置
std::vector<glm::vec2>      m_texcoords;       // 纹理坐标
std::vector<Material>       m_materials;       // 材质(diffuse/specular/emission + 贴图路径 + 参数)
std::vector<Instance>       m_instances;       // 实例 = {first_index, index_count} 索引范围
std::vector<uint32_t>       m_vertex_indices;  // 每三角形顶点索引
std::vector<uint32_t>       m_texcoord_indices;// 每三角形纹理索引
std::vector<uint32_t>       m_material_ids;    // 每三角形材质 ID
```

### 3.2 加载与归一化

`obj_load()` 使用 tinyobjloader 解析,并做:

1. **顶点归一化**:计算所有顶点的 AABB,把场景平移到原点并把最长边缩放到 [-1,1]:
   ```cpp
   vertex = (vertex - obj_center) * (2.0 / max_extent);
   ```
   这让后续相机默认参数(速度 0.5、near 0.01)在不同模型上表现一致;
2. **纹理坐标翻转 Y**:`texcoord.y = -texcoord.y`,把 OBJ 的 UV 原点(左下)转为 Vulkan/STB 的(左上);
3. **贴图路径解析**:相对路径拼接 OBJ 所在目录;
4. **非三角形面检查**:仅支持三角形面,否则报错;
5. **无材质/无 UV 兜底**:无 UV 时补一个默认 texcoord 并把所有索引填 0。

### 3.3 三种实例化策略(重要设计)

| 策略 | 实例数量 | 用途 |
| --- | --- | --- |
| `obj_single_instance` | 1 个实例 | 整个模型一个实例(当前 main 使用) |
| `obj_shape_instance` | 每 shape 一个实例 | 便于按 OBJ shape 做变换 |
| `obj_sah_shape_instance` | SAH 自动划分 | 按包围盒 SAH 代价递归合并 shape 成实例(最多 2^max_level 个,限制 ≤128 实例) |

**SAH 划分算法**是代码里最复杂的 CPU 逻辑之一,要点:

- 每个 shape 视为一个 `Reference`(含 AABB + 索引数据);
- `SplitSAH`:对 refs 按中心坐标在 X/Y/Z 三轴各排一次序,对每个左/右切分点计算表面积启发式代价 `SAH = left_size * SA_left + right_size * SA_right`(近似论文的 `n * A / A_root` 形式),选代价最小的切分;
- 若最优 SAH 不小于"不切分代价"`AABB_half_area * size`,则放弃切分(说明合并更优);
- 递归到 `max_level` 或无法切分(单 ref 且仅 1 三角形)为止;
- 划分后把每个 leaf 的三角形数据**物理重排**进全局索引数组,再按 leaf 生成 `Instance{first_index, index_count}`。

> 注释要点:`_AxisSplitSAH<Axis>` 用模板参数实例化三次,避免运行时分支;`right_aabbs` 后缀数组实现 O(n) 计算所有右半 AABB,整体复杂度 O(n log n)。

## 4. `VkScene` — GPU 场景资源

### 4.1 职责

把 `Scene`(CPU 数据)上传为 Vulkan 缓冲与贴图,并提供:
- 顶点/索引/UV/材质/材质 ID 缓冲(同时带加速结构构建所需的 usage);
- 贴图数组(去重 + 并发加载);
- 每个实例的变换矩阵缓冲(可映射,每帧更新);
- BLAS 几何描述(GPU 侧)。

### 4.2 GPU 侧数据结构对齐(重点)

```cpp
struct Material {                    // 与 Scene.glsl 的 Material 完全一致
    alignas(vec4) glm::vec3 diffuse; // 纹理 ID 紧跟在 vec3 后,占一个 vec4 槽
    uint32_t diffuse_texture_id;
    alignas(vec4) glm::vec3 specular;
    uint32_t specular_texture_id;
    alignas(vec4) glm::vec3 emission;
    uint32_t emission_texture_id;
    float metallic, roughness, ior;
};
struct Transform { glm::mat3 rotate; glm::vec3 translate; }; // 12 floats,存为 mat3x4
```

**`UpdateTransformBuffer` 的转置技巧**:

```cpp
ts[i] = glm::transpose(glm::mat4x3{t.rotate[0], t.rotate[1], t.rotate[2], t.translate});
```

GLSL 侧 `mat3x4 uTransforms[]` 按列主序存 12 个 float,而 GLM `mat3x4` 是行主序 16 字节对齐,直接 memcpy 会错位;先转置成 `mat4x3` 再写,恰好与 GLSL 的列主序布局一致。着色器里用 `vec4(v,1) * uTransforms[instance_id]`(行向量乘矩阵)完成实例变换。

### 4.3 缓冲上传

- 每个缓冲先 `CreateStaging` 拷进主机可见内存,再在单个一次性命令缓冲里 `CmdCopy` 到设备本地缓冲;
- 顶点/索引缓冲额外声明 `ACCELERATION_STRUCTURE_BUILD_INPUT_READ_ONLY` + `SHADER_DEVICE_ADDRESS`,供 BLAS 构建直接引用(免拷贝)。

### 4.4 贴图并发加载

`load_textures<Loads...>` 是一个**模板化多态纹理加载器**:

- 模板参数 `TexLoad{Scene::Material::p_path, Material::p_id}` 指定"从哪个 CPU 字段取路径、写哪个 GPU 字段的 ID";
- 用一个 fold expression 对 diffuse/specular/emission 三路统一处理,避免三段重复代码;
- 路径去重(同一贴图只加载一次);
- `std::async(load_texture)` × (硬件线程数-1) 并发加载,每个线程独立 CommandPool + 独立提交,原子分配路径 ID 与纹理 ID;
- 加载失败路径 ID 记 -1(着色器侧判断 `diffuse_texture_id == -1` 用常数颜色);
- 加载结束后弹出尾部空纹理,若无任何贴图则插入一张 1×1 白纹理兜底。

## 5. `VkSceneBLAS` — 底层加速结构构建

### 5.1 职责

为每个实例构建一个 BLAS,并做**紧凑化(compaction)**以节省显存。

### 5.2 构建流程

1. **预算**:对每个实例调用 `vkGetAccelerationStructureBuildSizesKHR` 得到 `accelerationStructureSize` 与 `buildScratchSize`,取所有实例 scratch 的最大值(共享一个 scratch buffer);
2. **分批构建**:按累计 `accelerationStructureSize` 是否超过 `kASBuildBatchLimit = 256MB` 分批次:
   - 每批一个命令缓冲,`vkCmdBuildAccelerationStructuresKHR` 逐实例构建;
   - 构建间插入 scratch buffer barrier(写后读写);
   - 批末用 `vkCmdWriteAccelerationStructuresPropertiesKHR` 查询压缩后尺寸(query pool);
3. **紧凑化**:`vkCmdCopyAccelerationStructureKHR` 以 `COMPACT` 模式把每个 BLAS 拷贝到更小内存,旧结构丢弃。

> 注释要点:`ALLOW_COMPACTION | PREFER_FAST_TRACE` 标志组合保证可压缩且追踪快;分批上限 256MB 控制单次命令缓冲内存峰值。TODO 注释提及未来可放异步计算队列。

### 5.3 为什么按实例建 BLAS

实例 = SAH 划分后的三角形子集,每个 BLAS 独立构建;TLAS 只存实例引用。这样:
- 实例间可以独立变换(矩阵在 TLAS 层);
- 场景重组(改实例矩阵)只需重建 TLAS,不用动 BLAS;
- 每个 BLAS 的三角形范围由 `GetInstanceBLASBuildRange` 给出(primitiveCount = index_count/3,primitiveOffset = first_index*4 字节)。

## 6. `VkSceneTLAS` — 顶层加速结构

### 6.1 职责

持有实例缓冲(`VkAccelerationStructureInstanceKHR[]`,CPU 可写映射)与 TLAS;提供 `UpdateTLAS()` 做**增量更新**。

### 6.2 实例缓冲与 customIndex(关键设计)

```cpp
m_p_instances[instance_id] = {
    .transform = GetVkTransform(instance_id),   // 3x4 行主序
    .instanceCustomIndex = primitive_id_base,    // 全局三角形起始 ID
    .accelerationStructureReference = blas[instance_id]->GetDeviceAddress(),
};
primitive_id_base += instance.index_count / 3;
```

`instanceCustomIndex` 记录**该实例在全局三角形数组中的起始 ID**。着色器里 `GetRayQueryHit` 用:
```cpp
primitive_id = rayQueryGetIntersectionInstanceCustomIndexEXT(...) +
               rayQueryGetIntersectionPrimitiveIndexEXT(...);
```
即"全局基准 + 实例内偏移",从而把 BLAS 内局部三角形 ID 映射回全局数组,一步定位顶点/UV/材质。

### 6.3 TLAS 构建/更新

```cpp
mode = m_tlas ? UPDATE : BUILD;   // 首次 BUILD,之后 UPDATE
srcAccelerationStructure = m_tlas; // 复用旧 TLAS
scratch 尺寸:updateScratchSize(更新)或 buildScratchSize(首次)
```

实例缓冲使用 `VMA_ALLOCATION_CREATE_MAPPED_BIT | HOST_ACCESS_SEQUENTIAL_WRITE`,CPU 直接改写变换矩阵,GPU 侧更新 TLAS 即可反映新姿态。`UpdateTLAS()` 当前未被 main 调用(模型静态),但接口保留。

## 7. `VkNRCState` — NRC 状态管理

### 7.1 职责

集中管理 NRC 相关的 GPU 状态与 CPU 控制参数:

| 成员 | 说明 |
| --- | --- |
| `m_weights` | fp16 权重缓冲(训练中更新) |
| `m_use_weights` | fp16 推理权重缓冲(渲染用) |
| `m_optimizer_state` | Adam 步数/β^t/α^t 标量状态(1 个 UBO) |
| `m_optimizer_entries` | 每权重的 `{m, v, weight, ema_weight}`(fp32) |
| `m_accumulate_view` | 时域累积图像(1280×720 rgba32f storage image) |
| `m_seed` / `m_rng` | 每帧随机种子 |

### 7.2 网络超参

```cpp
kNNHiddenLayers = 5;   // 5 个隐藏层
kNNWidth       = 64;   // 每层 64 神经元
kNNOutWidth    = 3;    // 输出 3(RGB)
kTrainBatchSize  = 16384; // 每训练批样本数
kTrainBatchCount = 4;      // 每帧 4 个训练批
kNNWeighCount = 64*64*5 + 64*3 = 20672  // 权重总数
```

### 7.3 权重初始化(He/Kaiming)

```cpp
std::normal_distribution<float> norm{0, std::sqrt(2.0f / kNNWidth)};
```

论文采用的 He 初始化(方差 2/n_in),避免深层 ReLU 网络梯度消失/爆炸。

### 7.4 `ResetMLPBuffers()` — 状态重置

1. 生成 fp32 权重 → 转 fp16 存 `m_weights` / `m_use_weights`;
2. 初始化优化器条目 `{weight, ema_weight}`,m/v 默认 0;
3. `OptimizerState{ t=0, beta1_t=1, beta2_t=1, alpha_t=1 }`;
4. 用三个 staging 缓冲 + 单命令缓冲拷贝到设备内存,`Fence::Wait()` 同步完成。

> 注释要点:所有缓冲都带 `TRANSFER_DST` 以便重置拷贝;`optimizer_state` 同时是 UBO(供优化器/准备 Pass 读取),`optimizer_entries` 是 fp32 存储缓冲(优化器用 fp32 维护,推理权重用 fp16 存储——精度与带宽的折中)。

### 7.5 记录缓冲大小

```cpp
GetEvalRecordBufferSize(extent) = (w*h + 16384*4) * sizeof(NRCEvalRecord)
```

为 eval records 预留 `像素数 + 所有训练批容量` 的空间——因为训练模式下每个像素最多追加一整个路径(最多 MAX_BOUNCE 个点)的训练记录,而 eval record 由路径追踪和推理共用同一缓冲(见 05 文档)。`NRCEvalRecord` 由 C++ 端 `struct` 与 GLSL 端 `struct` **手工保持内存布局一致**。

### 7.6 训练概率控制

```cpp
main 中:nrc_lock 时 SetTrainProbability(0),否则 SetTrainProbability(0.03)
```

即默认每帧约 3% 的像素子组进入训练模式(`subgroupElect` 选一个代表掷骰)。Lock 时可通过"Train 1-Frame"按钮手动训练一帧。

### 7.7 累积图像重置

`ResetAccumulateImage` 创建 rgba32f 存储图像并切换到 `GENERAL` 布局(供 ScreenPass 的 storage image 读写),resize 回调时调用。
