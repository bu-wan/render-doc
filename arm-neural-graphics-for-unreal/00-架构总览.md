## 1. 项目定位与功能

本仓库是 Arm 出品的 **Unreal 引擎神经图形插件**,提供两类面向移动端优化的渲染技术:

| 技术 | 全称 | 作用 | 实现方式 |
|---|---|---|---|
| **NSS** | Neural Super Sampling(神经超采样) | 以更低渲染分辨率 + 神经网络上采样,提升画质、降低渲染开销 | 实现引擎 `ITemporalUpscaler` 接口,替换 TAA 上采样 |
| **NFRU** | Neural Frame Rate Upscaling(神经帧率提升) | 通过帧插值生成中间帧,提升感知帧率 | 在 Present 阶段用神经网络插值出 1 帧插值帧,交替显示真实帧/插值帧 |

关键前提:

- **仅支持 Vulkan RHI**(依赖 `VK_ARM_tensors` + `VK_ARM_data_graph` 扩展),使用其他 RHI 时插件自动禁用并弹窗提示。
- 桌面开发调试依赖 **Arm ML Emulation Layer for Vulkan**(模拟层)或真实支持 ARM 扩展的驱动。
- 推理与超采样/插值的核心算法在 **Neural Graphics SDK for Game Engines(NG-SDK)** 中实现,插件侧只是"桥接层"——把 UE 的资源/命令列表/相机参数翻译成 NG-SDK 的调用。
- NG-SDK 的 API 与 **AMD FidelityFX API 兼容**(`ffx*` 前缀),因此插件大量代码沿袭 AMD FSR 系列插件结构。

## 2. 原理与算法分析(前置理论)

> 理解本节是读懂全部代码的前提。本节回答三个"为什么":为什么 NSS 能省性能、为什么 NFRU 能翻倍帧率、
> 为什么插件要绕这么多层(后端抽象、状态池、复制头)。

### 2.1 时序超分辨率(NSS)为什么有效

**成本侧**:渲染开销主要与像素数成正比(光栅化、像素着色、后处理)。保持输出分辨率不变,把渲染分辨率
降到一半,像素数降到 1/4,填充率瓶颈立即缓解;而"升采样到全分辨率"本身很便宜。这就是"超采样"省钱的根本原因。

**画质侧(为什么不是简单双线性放大)**:

1. **TAA 抖动(jitter)**:每帧把投影矩阵平移一个**子像素**偏移,使相邻帧的采样网格错开。
   单帧信息不足的高频细节,在多帧累积中信息互补——时间维度上等价于更高采样率。
2. **历史重投影**:上一帧全分辨率结果通过**运动矢量**重投影到当前帧,与当前帧低分辨率采样融合,
   把历史信息"搬运"到当前时刻,从而重建细节并抑制时间闪烁。
3. **NSS = 学习型 TAA**:NSS 的输入(当前帧低分辨率颜色、深度、运动矢量、jitter、曝光、上一帧输出)
   与引擎 TAA 几乎相同,但"如何融合历史与当前"不再由手工滤波核(如 Catmull-Rom + 反馈钳制)决定,
   而是由一个**神经网络**(量化模型,经 `VK_ARM_data_graph` 在 GPU 上执行)学习得出。
   网络内部还承担了边缘检测、去遮挡(disocclusion)处理、稳定性控制等传统 TAA 手工调参的工作。

**关键数据依赖**:

- **运动矢量**:建立"当前像素 ↔ 上一帧像素"的对应关系,是重投影的依据;UE 默认输出**稀疏**编码
  速度场,插件必须转成 SDK 要求的稠密格式(见 NGVulkanBackend 文档)。
- **深度**:区分前后景、处理遮挡/边缘;深度约定(是否反转)必须与 SDK flag 一致。
- **曝光**:输入为线性 HDR,曝光值用于网络内部色调归一化。
- **jitter**:告诉网络当前帧的采样偏移,网络才能正确对齐历史与当前。

### 2.2 帧生成(NFRU)原理

显示器刷新率(如 120Hz)高于游戏实际渲染帧率(如 60FPS)时,空闲的刷新周期被浪费。帧生成在
**两帧真实渲染帧之间合成一帧中间帧**,让显示端每两个刷新周期就看到一个新画面,感知帧率翻倍。

**合成算法**(SDK 内部,插件只喂数据):

1. **运动估计**:以当前帧运动矢量 + 深度为线索(optical flow hints),估计场景在两帧之间的真实运动。
2. **变形(warp)**:把上一帧颜色沿运动方向"搬运"到中间时刻,得到中间帧的主体内容。
3. **合成/修补**:结合当前帧信息修补遮挡与新出现区域,输出中间帧。

**为什么需要这些输入**:上一帧颜色(被 warp 的对象)、上一帧深度(遮挡关系)、当前帧深度/运动矢量
(运动线索)、相机视图投影矩阵(几何一致性)、jitter(与上采样链路对齐)、帧时间差(插值系数)。

**与 NSS 的关系**:NFRU 假设渲染分辨率低于显示分辨率(即 NSS 也在链路中),它工作在
NSS 上采样完成之后、Present 之前。

### 2.3 神经网络在 Vulkan 上的执行原理

- **`VK_ARM_tensors`**:tensor 作为一类 GPU 图像资源,可被着色器采样、也可被神经网络算子消费,
  是"模型输入输出"的载体。
- **`VK_ARM_data_graph`**:以"数据图"方式把神经网络表达为 GPU 上的算子图,一次提交执行完整网络,
  避免传统管线栈(每层一次 dispatch)的调度开销——这正是移动端神经网络渲染的关键。
- **桌面模拟**:消费级 GPU 驱动不支持上述扩展,因此需要 **ML Emulation Layer for Vulkan**
  (一个 Vulkan 实例层)在软件层面模拟扩展行为;插件还随包携带 **`VK_LAYER_ARM_NG`** 特性层
  为 SDK 提供额外能力。层/扩展**必须在 Vulkan 实例与设备创建前注册**,否则设备扩展列表里没有它们,
  运行期 `IsNeuralGraphicSupported()` 探测必然失败——这是代码里"模块启动立即注册"的原因。

### 2.4 FFX(FidelityFX 兼容)API 模型

NG-SDK 暴露的是典型的 **host/device 分离** 的 FFX 风格接口:

```
ffxCreateContext(desc + 后端描述 pNext)   // 一次性创建:分配内部资源、编译着色器、建立 data graph
ffxConfigure(desc)                        // 运行期配置变化(如 swapchain 绑定、调试开关)
ffxDispatch(desc)                         // 每帧执行(上采样 / 帧生成)
ffxDestroyContext()                       // 销毁
```

- 所有 `desc` 都以 `header.type` 区分类型,并可用 `header.pNext` 挂**扩展描述**(如 Vulkan 后端描述)。
- 插件不直接调 SDK:所有 `ffx*` 调用都经 `INGSharedBackend` 接口转发——因为 SDK 需要的是
  **原生句柄**(VkImage / VkCommandBuffer / VkDevice),而插件手里只有 UE 的 RHI 对象,
  必须由后端模块完成翻译。这就是"后端抽象"存在的根本原因。

### 2.5 GPU 异步执行与延迟删除

UE 渲染线程、RHI 线程、GPU 三者异步流水;CPU 侧释放资源时 GPU 可能仍在引用。
直接删除会造成悬挂指针/显存重用错误。因此插件采用两种"延迟"策略:

1. **状态池 + 延迟删除(NSS)**:`ffxContext` 持有大块显存(Data Graph 会话),频繁创建/销毁抖动严重。
   插件把闲置 context 放入 `AvailableStates` 池,只有闲置超过 `r.NG.DeferDelete`(默认 5)帧才真正销毁。
2. **延迟销毁队列(NFRU)**:`NFRUCustomPresent` 维护 `DeferredDestroyQueue`,同样按帧数延迟释放
   `NFRUResources`。

### 2.6 引擎版本适配原理(复制头 + 宏改写)

插件需要访问引擎**私有**成员(如 `FRDGBuilder` 内部纹理表、`FSlateApplication` 的渲染器指针),
但引擎源码不允许修改。方案:

1. 把引擎头文件**整体复制**进插件(如 `FRDGBuilder_5_4_0.h`),与引擎头**完全同构**;
2. 用宏在包含前改写:
   - `#define private protected` —— 私有成员变成受保护,派生类可以访问;
   - `#define FRDGBuilder FFXRDGBuilderBase` —— 类改名,避免与引擎同名类冲突;
3. 包含后撤销宏,插件自己的 `FFXRDGBuilder : FFXRDGBuilderBase` 派生类即可访问"原私有"成员;
4. 用 `static_assert(sizeof(引擎类) == sizeof(复制类))` 保证两份定义布局一致(引擎改了布局立即编译失败)。

### 2.7 compute vs fragment 着色器路径

- **compute 路径**:输出纹理以 UAV 绑定,中间结果需要写入/读回显存;通用、兼容性好。
- **fragment 路径**:输出以 RTV 绑定,整帧在移动 GPU 的 **tile 内存**内完成读写,
  省去中间显存往返,带宽与功耗显著更低——这是移动端默认启用 fragment 路径的原因。
- 代价:SDK 要为两种路径生成不同着色器变体;且模拟层(桌面 x86)对 fragment 读 tensor 有限制,
  代码里 `PLATFORM_CPU_X86_FAMILY` 分支会自动回退 compute/UAV。

## 4. 模块划分与依赖关系

每个插件由若干 UE 模块组成(见 `.uplugin` 的 Modules 列表):

| 模块 | 类型 | 加载阶段 | 职责 |
|---|---|---|---|
| **NGShared** | Runtime | PostConfigInit | 公共层:NG-SDK/FidelityFX 头文件封装、`INGSharedBackend` 后端抽象、`GetFFXApiFormat/GetUEAccessState` 格式转换、版本化引擎头文件复制(`FFXRDGBuilder`/`FFXSlateApplication`) |
| **NGSettings** | Runtime | EarliestPossible | 集中定义全部 CVar 与 `UNGSettings`(UDeveloperSettings,Editor UI),启动时从 ini 回放 CVar |
| **NGVulkanBackend** | Runtime | PostConfigInit | 加载 `ngsdk_*.dll/so`、注册 Vulkan 扩展/层、实现 `INGSharedBackend`(Vulkan)、速度场转换着色器 `NGConvertVelocity`、Android APL |
| **NSS** | Runtime | PostConfigInit | NSS 时序上采样:实现 `ITemporalUpscaler` + `IScreenSpaceDenoiser`,视图扩展注册、状态池、历史管理 |
| **NFRU** | Runtime | PostConfigInit | NFRU 帧生成:ViewExtension 采集输入、自定义 Present(`FRHICustomPresent`)、Slate 渲染器包装、FPS 调节器 |
| **SmokeTests** | Editor | PostConfigInit | 自动化冒烟测试(开关 NSS/Debug/MipBias 前后截图对比) |

                        └────┬─────┘
                             │

## 6. 渲染管线接入点(核心)

### 6.1 NSS —— 替换 TAA 上采样

- 通过引擎公开接口 **`UE::Renderer::Private::ITemporalUpscaler`**(`using INSS = ITemporalUpscaler`)接入。
- `NSSViewExtension::BeginRenderViewFamily` 判断:视图请求了 `PrimaryScreenPercentageMethod == TemporalUpscale` 且 `CVarEnableNSS` 打开时,调用
  `InViewFamily.SetTemporalUpscalerInterface(new NSSProxy(Upscaler))`,把引擎默认 TAA 上采样替换为 NSS。
- 引擎随后在 PostProcessing 里回调 `ITemporalUpscaler::AddPasses(RDGBuilder, View, Inputs)`,NSS 在此把
  SceneColor/SceneDepth/SceneVelocity + jitter + 相机参数交给 NG-SDK 做上采样,输出全分辨率颜色。
- 配套 CVar:`r.AntiAliasingMethod 2(或 4)`、`r.TemporalAA.Upscaler 1`、`r.TemporalAA.Upsampling 1`。
- 额外实现 `IScreenSpaceDenoiser` 并把自己注册为 `GScreenSpaceDenoiser`(包裹原 denoiser),以便
  捕获反射纹理等数据(历史遗留设计,当前主要透传)。

### 6.2 NFRU —— Present 阶段帧插值

- 输入采集:`NFRUViewExtension::PrePostProcessPass(_Mobile)_RenderThread` → `NFRU::SetupView`,
  记录每视图的 ViewFamilyTexture / SceneDepth / SceneVelocity / jitter / 相机参数。
- 插值执行:`GEngine->GetPostRenderDelegateEx().AddRaw(this, &NFRU::InterpolateFrame)`(每帧渲染线程,
  后处理完成、Present 之前)对每个视图调用 `InterpolateView`,最终走 NG-SDK 的
  `FFX_API_DISPATCH_DESC_TYPE_FRAMEGENERATION_PREPARE` + `…_FRAMEGENERATION` 两次 dispatch。
- 呈现控制:自定义 `NFRUCustomPresent : FRHICustomPresent` 挂在 `FRHIViewport` 上,
  `NeedsNativePresent()/Present()` 控制插值帧与真实帧交替呈现;Slate 侧用 `NFRUSlateRenderer`
  包装原 `FSlateRenderer`,在 `OnSlateWindowRendered` 时 `ForceRedrawWindow` 补画一帧。
- 调试 UI 提取:帧插值会破坏"只在首帧绘制的调试 UI",用计算着色器
  `PostProcessFFX_FIAdditionalUI.usf` 把 UI 差异合并到插值帧。

## 7. 每帧数据流

### 7.1 NSS(单帧)

```
SceneColor(低分辨率) ─┐
SceneDepth            ├─ CopyAndCropIfNeeded(裁剪/防越界) → NSS::AddPasses
SceneVelocity(稀疏)   ─┘        │
      │                        ▼
      │              NGConvertVelocity PS(速度场转换,PF_G16R16F,负速度*0.5 约定)
      │                        ▼
      │       构造 ffxApiDispatchDescNss(jitter、renderSize/upscaleSize、相机、reset)
      │                        ▼
      │       GraphBuilder.AddPass(UAV 或 RTV 路径)
      │         └→ RHI 线程 EnqueueLambda:ffxDispatch(FFX_API_DISPATCH_DESC_TYPE_NSS)
      │                        ▼
      └──────────► UpscaledOutputColor(R11G11B10, 全分辨率)
                     ├→ Outputs.FullRes(作为最终 SceneColor)
                     └→ QueueTextureExtraction → PrevFrameViewInfo.TemporalAAHistory.RT[0]
                          + NewHistory->UpscaledColour(下一帧 OutputTm1)
```

上下文复用:每个视图维护 `NSSState`(内含 `ffxContext`)。优先复用上一帧 history 携带的 state,
否则从 `AvailableStates` 池中挑"参数相同、非本帧已用、非其他视图"的 state,参数变化才重建 `ffxContext`。
`CVarNGDeferDelete`(默认 5 帧)控制池中闲置 state 的延迟销毁,避免反复分配/释放大块显存资源
(原理见 §2.5)。

### 7.2 NFRU(双帧节奏)

```
帧 N(真实帧):  引擎渲染 → InterpolateFrame:
                 BackBuffer 拷贝到 BackBufferRT[Index](双缓冲 ping-pong)
                 用帧 N-1 颜色(BackBufferRT[(Index+1)%2])、深度、速度 → ffxDispatch(Prepare+Interpolate)
                 输出 InterpolatedRT(或直接写回 BackBuffer)
                 Slate 重画 → Present 插值帧
帧 N+1(真实帧): 引擎渲染 → 正常 Present 真实帧;NFRU 再次插值…… 交替呈现
```

- 插值帧的呈现走"Slate 强制重绘 + CustomPresent 状态机"(`InterpolateRT→InterpolateRHI→PresentRT→PresentRHI`)。
- `ResetState` 倒计数保证首 3 帧不插值(等待历史稳定)。
- FPS 调节器(`r.NFRU.PaceAdjuster`):按空闲时间统计升降频(`Upcount/Downcount` 阈值见
  `r.NFRU.UpAdjustFrameCount`=40 / `r.NFRU.DownAdjustFrameCount`=20),动态修改 `r.SetFramePace`。

## 8. 引擎版本适配机制(重要)

插件需要访问引擎**私有**成员(如 `FRDGBuilder::Textures` 找 Lumen 反射纹理、
`FSlateApplication::Renderer/LastTickTime`),但不允许改动引擎源码。方案是 **复制引擎头文件并按需改写**(原理见 §2.6):

1. 把引擎头文件原样拷贝到 `NGShared/Public/FRDGBuilderVersions/FRDGBuilder_5_4_0.h`、
   `FSlateApplicationVersions/FSlateApplication_5_4_0.h`(5.6 为 `_5_6_0` 版本)。
2. 用宏技巧改变可见性/类名后包含(见 `FFXRDGBuilderBase.h` / `FFXSlateApplicationBase.h`):
   ```cpp
   #define private protected          // 私有成员变受保护,子类可访问
   #define FRDGBuilder FFXRDGBuilderBase  // 类改名,避免与真类冲突
   #include FFX_BUILD_VERSIONED_INCLUDE_PATH(RDGBuilder)  // 展开为对应版本头
   #undef FRDGBuilder
   #undef private
   ```
3. `FFXRDGBuilder : FFXRDGBuilderBase` 添加 `FindTexture(TCHAR* Name)`;并用
   `static_assert(sizeof(FRDGBuilder)==sizeof(FFXRDGBuilder))` 保证内存布局一致。
4. `NGShared.h` 定义宏 `UE_VERSION_AT_LEAST(major,minor,patch)` 与
   `FFX_BUILD_VERSIONED_INCLUDE_PATH(name)`,实现按 `ENGINE_MAJOR/MINOR_VERSION` 自动选版本头。

> 对新引擎(宏检查上限被触发)会 `#error "Unsupported Unreal Engine 5 version"`,
> 即移植新引擎需同步更新复制头(步骤见模块文档 07)。

## 10. 构建与打包

### 10.1 NG-SDK 构建(5.x 分支:BuildSDK.py;4.27 分支:BuildSDK.bat)

- `BuildSDK.py` 是统一入口:`python BuildSDK.py -b vk_windows_x64|vk_linux_x64|vk_linux_arm|vk_android_arm [-t Debug|Release|RelWithDebInfo] [-j N] [--clean] [--toolchain …] [--vulkan-lib …]`。
- 实际调用 `Source/NG-SDK/build.py`,CMake 参数含 `-DFFX_BUILD_NGLAYER=ON`(构建 Vulkan 特性层)。
- 产物按平台复制到 `Binaries/ThirdParty/PreBuiltNGSDK/`:
  - Windows:`ngsdk_windows_x64[.dll/.lib/.pdb]` + `VkLayer_arm_NG.dll` + `VkLayer_arm_NG.json`
  - Linux:`libngsdk_linux_{x64,arm}.so` + `Linux(或 LinuxArm64)/libVkLayer_arm_NG.so` + json
  - Android:`libngsdk_android_arm.so` + `libVkLayer_arm_NG.so`
- `NGVulkanBackend.Build.cs` 在编译期检查预构建产物;缺失时**自动调用 BuildSDK.py**,并把
  DLL/SO 加入 `RuntimeDependencies`(随包分发)与 `PublicDelayLoadDLLs`。

### 10.2 模块源码路径约定

- 着色器虚拟路径:`/Plugin/NG` → 插件根 `Shaders/`(由 NGVulkanBackend 注册映射;4.27 分支用 `/Plugin/NSS`)。
- 4.27 分支在 `NSS.cpp` 内 `IMPLEMENT_GLOBAL_SHADER(FNssConvertVelocity, "/Plugin/NSS/Private/NssConvertVelocityPS.usf", …)`
  与 `FNssMirrorPadPS`;5.x 分支在 `NGConvertVelocity.cpp` 内
  `IMPLEMENT_GLOBAL_SHADER(NGConvertVelocity, "/Plugin/NG/Private/NGConvertVelocity.usf", "main", SF_Pixel)`。

### 10.3 Android 打包

- `NGVulkanBackend_APL.xml` 作为 `AdditionalPropertiesForReceipt("AndroidPlugin")` 接入 UAT,
  把 `libngsdk_android_arm.so` 与 `libVkLayer_arm_NG.so` 拷入 `libs/arm64-v8a/`,并在启动时 `loadLibrary("ngsdk_android_arm")`。
- Android 的 Vulkan loader(API≥28)自动发现 `libVkLayer_*.so` 特性层,无需注册实例层。

## 11. 平台 / 功能矩阵与已知边界

- RHI:仅 Vulkan(4.27 分支支持 ES3.1 + SM5;5.x 分支支持 ES3.1、SM5、SM6)。
- 平台:Windows x64、Linux x64/Arm64、Android arm64。
- NFRU 后端缓冲格式限制(Windows 检查):`PF_R8G8B8A8 / PF_B8G8R8A8 / PF_FloatR11G11B10 / PF_R8`,不满足则禁用并弹窗。
- NSS 的 `r.ScreenPercentage` 强制区间 (0,100),越界自动重置为 50;低于 35 会有已知画质问题。
- NSS 调试视图布局见 `r.NSS.Debug` 帮助文本(4 行×4 列:history_color/input_depth/prev_depth/…)。
- 已知怪癖:桌面 x86 模拟层下 fragment 路径读取 tensor 受限,自动回退 compute/UAV 路径
  (`PLATFORM_CPU_X86_FAMILY` 分支);`r.Stat FrameGen` 与 NFRU 同开会 UI 闪烁(建议 `r.NFRU.OnlyInterpolatedFrames 1`)。
