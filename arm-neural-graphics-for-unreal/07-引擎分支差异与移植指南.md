# 模块文档 07:引擎分支差异与移植指南

> 本仓库同时维护 UE4.27 与 UE5.x 两代引擎分支的插件。理解差异是在新引擎分支上重新实现的基础。
> 本文档不记录发布版本号/日期(由 git 管理),只描述**代码层面的技术差异**与移植步骤。

## 1. 引擎分支差异总表

| 维度 | UE4.27 分支 | UE5.x 分支 |
|---|---|---|
| 插件名 / 清单 | `NSS.uplugin` | `NG.uplugin` |
| 模块 | NGShared、NGSettings、NSS、NGVulkanBackend、SmokeTests(5 个) | 上述 + NFRU(6 个) |
| NFRU | ✘ | ✔ |
| NSS fragment 路径 | ✘(仅 compute) | ✔(`r.NSS.UseFragmentShader`,默认 1) |
| NSS 质量模式 | ✘ | ✔(`r.NSS.ShaderQualityMode`) |
| 加载阶段 | NGShared=Default、NGSettings=PreDefault、NSS/NGVulkanBackend=PostConfigInit、SmokeTests=PostEngineInit | NGShared/NSS/NGVulkanBackend/NFRU/SmokeTests=PostConfigInit、NGSettings=EarliestPossible |
| 着色器虚拟路径 | `/Plugin/NSS` | `/Plugin/NG` |
| 着色器 | `NssConvertVelocityPS.usf`(compute 风格)、`NssMirrorPad.usf` | `NGConvertVelocity.usf`(PS)、`PostProcessFFX_FIAdditionalUI.usf` |
| 引擎私有头复制 | 无(不需要) | `FRDGBuilder_5_x_0.h`、`FSlateApplication_5_x_0.h` |
| SDK 构建 | `BuildSDK.bat`(仅 Windows,cmake -A x64,拷到 `NG-SDK/prebuilt_binaries`) | `BuildSDK.py`(跨平台,拷到 `Binaries/ThirdParty/PreBuiltNGSDK/`) |
| 帧计数器 | `#define GFrameCounterRenderThread GFrameNumberRenderThread` | 引擎原生 `GFrameCounterRenderThread` |
| 延迟删除(`r.NG.DeferDelete` 状态池) | 无(history 直接销毁 state) | ✔(NSS 池 + NFRU DeferredDestroyQueue) |
| NSS 输入裁剪 | `CopyAndCropIfNeeded(PaddingOnOutput)`(裁剪 padding) | `CopyAndCropIfNeeded(CroppedSize)` + 1×1 零纹理保护 |
| 深度输入 | NSS 输入含 `DepthTm1Texture`(上一帧深度由插件管理) | NSS 无 DepthTm1(由 SDK 管理);NFRU 按 `MANAGE_PREVIOUS_DEPTH` 决定 |
| NSS API 能力 | 旧 ffx_api 枚举(无质量模式、无 fragment flag) | 新枚举(`FFX_API_NSS_CONTEXT_FLAG_*_FRAGMENT`、`FfxApiNssShaderQualityMode`) |

### 1.1 差异的技术原因(为什么 4.27 分支功能少)

- **NFRU 缺失**:帧生成依赖 Slate 渲染器包装与 `FRHICustomPresent` 的完整配合,以及
  `VK_ARM_data_graph_optical_flow` 扩展;4.27 分支的 SDK 对接面较旧,未包含该能力,
  且 4.27 的 Slate/渲染线程模型与 5.x 差异大,移植成本高——因此 4.27 分支定位为"仅 NSS"。
- **fragment 路径与质量模式**:这是 SDK 新 API 提供的能力(需要新枚举与着色器变体),
  4.27 分支锁定的旧 SDK 接口不支持,故只有 compute 路径与单档质量。
- **延迟删除**:是稳定性修复引入的机制(状态池 + 帧数延迟),4.27 分支未回溯该修复,
  history 直接销毁 context(存在反复分配显存的抖动,但功能可用)。
- **引擎私有头复制**:只有 5.x 分支的 NFRU 需要访问 `FSlateApplication` 私有成员,
  NSS 在 4.27 分支用不到,故无复制头。

### 1.2 UE4.27 分支特有实现细节

- `NSS.cpp` 顶部:
  ```cpp
  #define GFrameCounterRenderThread GFrameNumberRenderThread
  IMPLEMENT_GLOBAL_SHADER(FNssConvertVelocity, "/Plugin/NSS/Private/NssConvertVelocityPS.usf", "main", SF_Pixel);
  IMPLEMENT_GLOBAL_SHADER(FNssMirrorPadPS, "/Plugin/NSS/Private/NssMirrorPad.usf", "MirrorPadPS", SF_Pixel);
  ```
- `NSSPass::FParameters` 含 `DepthTm1Texture`(上一帧深度作为额外输入),5.x 分支的 NSS 已移除。
- `MirrorPad` 是镜像填充着色器,用于为 SDK 输入做边缘填充(5.x 分支该职责移交 SDK 内部)。
- NSS 关闭时同样输出黄色 Blank 纹理;但无 `bNeedsHistoryReset/BlockUntilGPUIdle` 逻辑。
- 无 `UE_VERSION_AT_LEAST` 宏体系(引擎分支固定),`IsPlatformSupported` 直接查特性级别。

## 2. 新引擎分支移植清单(以 UE5.4 → UE5.6 为模板)

### 2.1 复制并调整目录

1. 复制现有 5.x 分支目录为新分支,保留目录结构。
2. 引擎 API 差异:
   - 检索全仓 `UE_VERSION_AT_LEAST / UE_VERSION_OLDER_THAN` 分支(如 `ConfigUtilities`、
     `DataDrivenShaderPlatformInfo`、`bit` 头、`ERenderTargetTexture` 参数、
     `RHIGetViewportBackBuffer` 等),按新引擎 API 修正。
   - 引擎 Renderer/Internal 头文件接口变化(如 `ITemporalUpscaler::FInputs/FOutputs`、
     `FPostProcessingInputs`、`FMobilePostProcessingInputs`)需对照新引擎源码调整。

### 2.2 更新版本化复制头

1. 从新引擎源码复制 `Runtime/RenderCore/Public/RenderGraphBuilder.h` →
   `NGShared/Public/FRDGBuilderVersions/FRDGBuilder_<M>_<m>_0.h`。
2. 从新引擎源码复制 `SlateApplication.h` →
   `NGShared/Public/FSlateApplicationVersions/FSlateApplication_<M>_<m>_0.h`。
3. 更新 `FFXRDGBuilderBase.h` / `FFXSlateApplicationBase.h` 的 `#error` 上限。
4. 保持 `static_assert(sizeof(...))` 成立(引擎改动后若失败,说明复制头与引擎不一致)。

### 2.3 NG-SDK 子模块与预编译产物

1. `git submodule update --init --recursive`(SDK 子模块)。
2. 检查 `ffx_api` 枚举/`ffx_nss.h`/`ffx_framegeneration.h` 的破坏性变更,
   同步修改 `NGShared.h`、`NSSInclude.h`、`NSS.cpp`(context/dispatch 参数)、`NFRU.cpp`。
3. 重新构建 SDK:`python BuildSDK.py -b vk_windows_x64`(或对应平台),产物进 `Binaries/ThirdParty/PreBuiltNGSDK/`。

### 2.4 引擎补丁(移动端)

- NSS(ES3.1):需引擎 Mobile TAA 补丁 + `r.Mobile.AntiAliasing 2`、`r.Mobile.SupportsGen4TAA 1`。
- NFRU(ES3.1):需引擎移动渲染器补丁(允许后处理阶段访问速度/深度)。
- 移植时先确认新引擎是否已包含等价修复(新版引擎可能已官方合入)。

### 2.5 验证

1. 编辑器 + Vulkan RHI 启动无警告;`r.NSS.Debug 1` 出现调试视图;
   `ShowFlag.VisualizeTemporalUpscaler 1` 报告 NSS。
2. `r.NFRU.ShowDebugView 1` 显示插值调试视图;统计 Present FPS ≈ 2×渲染 FPS。
3. 跑 SmokeTests(`NG.PluginTests.*`)验证开关/截图流程。
4. 检查移动端(ES3.1)与 SM5/SM6 着色器平台编译通过。

## 3. 重新实现整仓能力的步骤建议(从零)

> 目标:不依赖本仓库,按文档重建插件。建议顺序(每步完成即自测):

1. **搭建骨架**:按本文档建 6 模块;写 `.uplugin`/`Build.cs`
   (NGShared 先落地:SDK 头路径、`UE_VERSION_AT_LEAST`、版本化包含宏)。
2. **NGSettings**:CVar 全量落地 + `UNGSettings` 编辑器界面(文档 02)。
3. **NGVulkanBackend**:LoadDLL + 扩展/层注册 + `INGSharedBackend` 实现 + 速度转换着色器(文档 03)。
   验证:`IsNeuralGraphicSupported()` 返回 true(需 ML 模拟层/驱动)。
4. **NGShared 补齐**:`GetFFXApiFormat/GetUEAccessState` + FFXRDGBuilder/FFXSlateApplication 复制头(文档 01)。
5. **NSS**:接口实现 + ViewExtension + AddPasses + 状态池/历史(文档 04)。里程碑:低分辨率渲染出全分辨率画面。
6. **NFRU**:ViewExtension 采集 + InterpolateFrame + CustomPresent + Slate 包装 + UI 捕获着色器
   + FPS 调节(文档 05)。里程碑:Present FPS 翻倍。
7. **SmokeTests + 构建脚本**(文档 06;BuildSDK.py/bat 逻辑见架构总览 §10)。
8. 质量收尾:延迟删除、1×1 资源保护、关闭时的 BlockUntilGPUIdle+历史重置、
   x86 模拟层 fragment 回退等"坑"全部照文档 04/05 的复现要点落实。

## 4. 常见坑速查

- 扩展注册时机晚了 → 设备扩展缺失,`IsNeuralGraphicSupported` 失败。
- `desc->pNext` 未挂 Vulkan 后端描述 → SDK context 创建失败。
- 速度场符号/半像素约定错 → 上采样结果漂移/鬼影。
- `r.ScreenPercentage` 越界 → NSS 直接禁用(见 `OnChangeScreenPercentage`)。
- 后缓冲格式不支持(Windows NFRU)→ 弹窗禁用。
- 复制头与引擎不匹配 → `static_assert` 失败或内存越界。
- Android 缺 `libVkLayer_arm_NG.so` → loader 找不到层,扩展不可用。
- 忘记 `Flush`(RHIFinishExternalComputeWork)→ 外部计算未同步,画面撕裂/挂起。
- 帧率调节未恢复 → 关闭 NFRU 后帧率卡在插值档位。
